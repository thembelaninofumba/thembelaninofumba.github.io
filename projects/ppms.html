Ask me about this work ↗

The context

Programme monitoring brings together plans, indicators, submissions, and reporting. Giving outcomes and impact a place in the data model helps connect programme activity with the wider results the reporting needs to describe.

My contribution

I contributed database updates to include outcomes and impact. This is reflected in the project’s commit history under my name.

PPMS is a collaborative departmental project. This case study describes my evidenced database contribution; the wider system was developed by the team.

The wider application

The PHP application includes programme and indicator reporting, budget views, risk reporting, and submission/review workflows. The repository also includes reporting endpoints for programme outcomes and performance.

My work sits within that larger reporting environment, improving how the database represents the relationship between programme information, outcomes, and impact.

What this work reinforces

A dashboard starts before the chart. Clear definitions and a suitable data structure make it easier for teams to capture information consistently and report on the questions that matter.
